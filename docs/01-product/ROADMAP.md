# MailDeck 版本规划

更新日期：2026-10-24

## 1. 版本策略

- 版本号遵循语义化版本；0.x 阶段 minor 为功能版本，patch 为修复版本。
- 版本范围以本文档为准；范围调整先改本文档并同步更新日志（`04-changelog/`），再进入开发。
- 版本发布需通过该版本验收门槛，并完成 [DEVELOPMENT.md](../03-process/DEVELOPMENT.md) 第 4 节发布流程。

## 2. v0.1.0 — QQ 邮箱多账号接收阅读闭环（当前版本，开发中）

目标：用户可以添加多个 QQ 邮箱账号（授权码），在统一收件箱中阅读邮件、同步已读状态，离线可查看已缓存内容；单个账号故障不拖累其他账号。

### 2.1 功能范围

| 能力 | 范围 | 完成标准 |
| --- | --- | --- |
| 账号管理 | 添加多个 QQ 邮箱账号，设置显示名称与颜色，暂停同步、移除账号 | 每个账号可独立连接、暂停和恢复 |
| 统一收件箱 | 所有账号合并显示，支持按账号切换 | 每封邮件标注所属账号，时间排序稳定 |
| 邮件列表 | 发件人、主题、收件时间、未读状态、附件标识 | 分页加载，加载旧邮件时保留当前位置 |
| 邮件阅读 | 纯文本与经 ammonia 安全处理的 HTML 正文 | 正确处理常见编码、内嵌图片及多部分邮件 |
| 已读管理 | 标记已读、未读并同步回 QQ 服务端 | 读取正文不误触其他邮件；失败有明确反馈 |
| 基础检索 | 已同步范围的发件人、主题搜索，按账号、未读筛选 | 中文主题可检索；界面说明检索范围 |
| 附件 | 展示名称、类型、大小，用户主动下载保存 | 正文加载不自动下载附件；失败可重试 |
| 同步状态 | 自动接收、手动刷新、最后同步时间与失败原因 | 单账号失败不阻塞其他账号；错误可分类 |
| 本地缓存 | 已同步列表与已打开正文 | 离线可查看；未缓存正文有清楚提示 |
| 服务商适配 | QQ（`imap.qq.com`，授权码） | 认证与连接差异收敛在适配层，同步核心无服务商分支 |

不在 v0.1.0 范围：发信、回复、转发、SMTP、新邮件通知、批量操作、正文检索、多文件夹、云端账号与同步、QQ 以外的邮箱服务商（取舍背景见 PLAN.md 第 3 节）。

### 2.2 验收门槛

- 至少两个 QQ 邮箱账号同时在线，完成多账号合并查看。
- 5 个账号规模下，持续接收期间界面保持可操作，失败账号不拖累其他账号。
- 首次加载范围清楚；加载旧邮件不重复、不漏过已确认同步的邮件。
- 已读、未读操作在 QQ 邮箱服务端可验证；失败或待同步状态可见。
- 其他客户端移走邮件后，本地收件箱经同步正确反映变化。
- 常见中文邮件、HTML、纯文本、附件及内嵌图片可阅读；异常邮件不阻塞账号。
- 重启、断网、休眠唤醒、QQ 授权码失效后，均有明确且可恢复的状态。
- HTML 正文不能执行脚本或自动打开外部页面；远程图片遵循设置。
- 授权码不出现在源码、普通配置和日志中。
- 移除账号只清理本地数据，QQ 邮箱中的原始邮件不变。

## 3. v0.2.0 — 通知与效率（候选）

| 能力 | 说明 |
| --- | --- |
| 新邮件通知 | 系统通知，配合托盘常驻 |
| 系统托盘 | 关闭窗口后的运行方式随之确认（PLAN.md 第 2 节遗留项） |
| 批量已读 | 列表多选操作 |
| 本地收藏 | 标记重要邮件 |
| 正文检索 | 依赖 v0.1.0 对 FTS5 中文方案的验证结论 |

进入条件：v0.1.0 同步与阅读链路稳定，按实际使用反馈排定优先级。

## 4. v0.3.0 — 文件夹与整理（候选）

更多邮件文件夹、移动邮件、规则分类。进入条件：先确定与服务端文件夹及状态的一致性规则。

## 5. 后续版本

新增邮箱服务商按实际需要接入，候选包括 Outlook（OAuth2）、163、Gmail 等；每新增一家须在 TECH_STACK.md 第 3 节登记接入方案并通过对应验证。Outlook 曾计划纳入 v0.1.0，已确认延后（见 TECH_STACK.md 决策记录）。
