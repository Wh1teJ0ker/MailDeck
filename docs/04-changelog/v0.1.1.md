# v0.1.1 更新日志

状态:开发中(未发布)

## 新增

- 设置新增「凭证存储」选项:默认系统凭证库(keyring,推荐);可显式切换为本地加密文件(AES-256-GCM,机器绑定密钥,界面说明保护范围)。切换时自动迁移全部账号的授权码,失败账号逐一列出且授权码保留在原存储。设置由后端 settings.json 所有,切换/迁移逻辑有单元测试覆盖;安全红线文档同步修订。
- 本地数据静态加密:邮件数据库整体切换为 SQLCipher(AES-256)加密,落盘文件不再含明文 schema/正文,检索功能不受影响;v0.1.0 明文库首次打开自动迁移(数据保留,迁移校验通过后删除明文原件);凭证本地文件模式同步改为 AES-GCM 加密。
- 163 邮箱适配:添加账号弹窗可选 163(客户端授权密码),连接后自动上报 IMAP ID(网易系要求),中文文件夹(UTF-7)解码分类,多文件夹同步/阅读/已读回写全链路与 QQ 一致。
- 服务商注册表升级:端点参数(主机/端口/是否要求 ID)并入注册表,连接统一经 `connect_for` 按账号服务商分发;真实账号冒烟用例 `tests/provider_163.rs` 就绪。

## 修复

- 同步管线文件夹分类改用解码后的显示名:此前用 UTF-7 原始名分类,163 的「已发送」等文件夹会被误判为「其他」而不同步。

## 变更

- 登录失败错误归因:QQ 返回的 AUTHENTICATIONFAILED 现翻译为中文排查清单(IMAP 服务开关/授权码/密码变更/频率限制/账号状态),并保留服务器原始信息;163 的 Unsafe Login 亦有对应提示。
- 减少 IMAP 登录次数:打开收件箱未读邮件时,拉正文与已读回写共用一条连接(此前一次操作登录两次);「全部已读」单账号失败(如被限流、授权失效)只记录到该账号状态,不再中断其他账号。这两项是对 QQ 登录频率限制的针对性缓解;彻底方案(每账号常驻连接)在 ROADMAP 后续项中。
- 架构优化(代码审计轮,报告见 docs/05-design/code-audit-2026-10-25.md):移除全局数据库互斥锁——数据层改为按命令短生命周期连接(WAL 多读并发 + busy_timeout),同步/拉正文期间不再阻塞列表查询等一切命令;TLS 连接器进程级缓存(不再每次连接重载系统根证书);SQLite 外键/busy_timeout/synchronous 显式声明(不再依赖 bundled 编译旗标的隐式行为),新增重开库级联回归测试;清理死参数。
- 流程纪律:未完成完整本地测试(`pnpm verify` 全绿)前禁止推送到远程仓库;该规则已写入开发流程(DEVELOPMENT.md 第 2、3 节),远程无 CI 第二道防线,本地校验是唯一闸门。
