## 记录规则

- 变更条目写入当前开发版本的文件（现为 v0.1.0.md），按 新增 / 变更 / 修复 三类组织。
- 版本发布时：该版本文件补发布日期并定稿；新建下一开发版本的日志文件；在本表追加一行。
- 格式参考 Keep a Changelog，版本号遵循语义化版本；发布流程见 [DEVELOPMENT.md](../03-process/DEVELOPMENT.md) 第 4 节。
- **每个已发布版本的 Release 页面说明 = 本目录对应文件的正文**（发布流水线自动注入；文件缺失则构建失败）。因此打 tag 前必须先定稿对应日志，发布后其内容即 GitHub Release 的更新说明。
